# @mridang/webhint-hint-extra

Extra [webhint](https://webhint.io) hints for sites and the APIs next to them. They cover what the stock hints leave out: security headers, Open Graph and SEO, agent readiness, privacy, DNS, TLS, email and the well-known files (`robots.txt`, `security.txt`, `llms.txt`, `ai.txt`).

286 hints in total. Every check is ported from a public reference, listed under [References](../../README.md#references), with the original rules, thresholds and wording kept.

## Install

```sh
npm install --save-dev hint @hint/connector-puppeteer @hint/parser-html @mridang/webhint-hint-extra
```

Node 22 or later is needed, and a Chrome or Chromium install for the `puppeteer` connector.

## Use

Each group is a ready-made preset in `configs/<group>.json` (see [Groups](#groups)). Extend the ones you want in `.hintrc`:

```json
{
  "formatters": ["stylish"],
  "extends": [
    "./node_modules/@mridang/webhint-hint-extra/configs/observatory.json",
    "./node_modules/@mridang/webhint-hint-extra/configs/owasp.json",
    "./node_modules/@mridang/webhint-hint-extra/configs/email.json"
  ]
}
```

Every preset names the `puppeteer` connector and the `html` parser, which a project's own `.hintrc` can override. Then scan:

```sh
npx hint https://example.com/
```

Single hints are listed as `@mridang/webhint-hint-extra/<id>`, with the ids from the [Hints](#hints) table. Use `default` as the severity so each hint keeps the level its rule defines (`error` for a failed rule, `warning` for advice, `hint` for information):

```json
{
  "connector": { "name": "puppeteer" },
  "parsers": ["html"],
  "formatters": ["stylish"],
  "hints": {
    "@mridang/webhint-hint-extra/csp": "default",
    "@mridang/webhint-hint-extra/hsts": ["default", { "profile": "owasp" }]
  }
}
```

A few hints take options:

| Hint                                                                        | Option               | What it does                                                                                                |
| --------------------------------------------------------------------------- | -------------------- | ----------------------------------------------------------------------------------------------------------- |
| `csp`, `hsts`, `coop`, `coep`, `corp`, `referrer-policy`, `x-frame-options` | `profile`            | `observatory` (the default) applies Mozilla Observatory's rule, `owasp` the OWASP recommended value.        |
| `cache-control`                                                             | `enforce` (boolean)  | Off by default. When `true`, requires `Cache-Control: no-store, max-age=0`, as private applications should. |
| `clear-site-data`                                                           | `logoutUrl` (string) | Off by default. When set, fetches that URL and checks it answers with `Clear-Site-Data`.                    |

For a report that groups the findings by section and shows each hint's description and sources, add [`@mridang/webhint-formatter-extra`](../formatter/README.md). To run every hint without writing a `.hintrc`, use the [`plumbline` CLI](../cli/README.md).

### Before the first release

Until the package is on npm, build it from this repository and install the tarball into a scratch folder:

```sh
devbox run -- npm run build
devbox run -- npm pack ./packages/hints --pack-destination "$(mktemp -d)"
```

`npm pack` prints the path of the tarball; install it with `npm install hint @hint/connector-puppeteer @hint/parser-html /path/to/mridang-webhint-hint-extra-0.0.0.tgz`.

## In the browser

The package also loads in a browser, which is how the [plumbline site](../web/README.md) runs it. It imports Node's socket, TLS, process, crypto and file modules through the conditional imports in `package.json` (`#net`, `#tls`, `#child_process`, …): Node gets `src/node/`, browsers get `src/browser/`, whose stand-ins refuse, so a hint that needs a raw connection is reported as skipped there.

## Development

Commands run from the repository root through devbox. [`AGENTS.md`](../../AGENTS.md) explains how a hint is written, registered and tested.

```sh
devbox run -- npm run build
devbox run -- npx jest --coverage=false packages/hints
devbox run -- npx eslint packages/hints
```

## Groups

A hint can belong to several groups, so a whole source or a whole topic can be switched on at once. Each group is a ready-made preset in `configs/<group>.json`; extend one or several as shown under [Use](#use).

| Kind   | Groups                                                                                                                                                                                                       |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Source | `observatory`, `owasp`, `opengraph`, `agent-ready`, `webbkoll`, `internetnl`, `files`, `llmscout`, `original`, `mdn`, `iab`, `google`, `w3c`, `ietf`, `indieweb`, `apple`, `oembed`, `opensearch`, `roctify` |
| Topic  | `security-headers`, `tls`, `dns`, `privacy`, `seo`, `social`, `email`, `agent`, `pwa`                                                                                                                        |

The source groups keep the original grouping of each reference, so a source can be enabled or disabled as a whole.

## Sections

Every hint is sorted into one section, which is also the sidebar of the report. A hint can carry tags for other sections it touches. The sections were proposed by two teams of reviewers, one arguing from what a site owner wants and one from protocols and layers, and settled by a judge; where a placement was a close call, who usually has to make the fix decided it.

| Section                 | Hints | What it holds                                                                                                                                                                                                                                               | Usually fixed by                                                        |
| ----------------------- | ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| LLMs and AI             | 34    | Everything that tells bots and AI systems what they may read and how to use you: robots.txt, llms.txt, ai.txt, AI crawler rules, Content Signals, agent discovery, auth and payment protocols, Web Bot Auth, markdown negotiation and answer-engine markup. | site content, files at the web root and /.well-known, web server config |
| Search and page quality | 57    | Be found and understood by search engines: titles, descriptions, headings, lang, canonical, robots meta, JSON-LD, alt text, image weight, redirect chains.                                                                                                  | site content and templates                                              |
| Link previews and icons | 44    | How the site looks when shared or bookmarked: Open Graph, Twitter/X cards and favicons.                                                                                                                                                                     | site content and templates (the HTML head)                              |
| HTTPS and certificates  | 20    | Visitors reach the real site over a trusted encrypted connection: TLS versions, ciphers, certificates, mail-server STARTTLS, compression risk.                                                                                                              | web server or CDN TLS config                                            |
| Site protection         | 67    | Make the site hard to attack from a browser: CSP, framing, cross-origin policies, CORS, cookie flags, HSTS-adjacent header rules, deprecated headers, private-page caching, security.txt.                                                                   | web server or application config (response headers)                     |
| Visitor privacy         | 15    | What the site reveals about its visitors: cookies, third-party requests, localStorage, geolocation, referrer and DNS-prefetch leakage, third-party report endpoints, and the privacy policy and terms it links.                                             | site content, scripts and header config                                 |
| Email security          | 30    | Mail sent as your domain is trusted and cannot be spoofed: SPF, DKIM, DMARC, STARTTLS, and DNSSEC, DANE, IPv6 and RPKI of the mail servers.                                                                                                                 | mail admin / mail DNS records                                           |
| DNS and network         | 15    | The domain, name servers and web server are reachable and tamper-resistant: DNSSEC, IPv6, RPKI, DANE and CAA.                                                                                                                                               | DNS zone, registrar, hosting/network provider                           |
| Progressive Web App     | 4     | The page is installable and themed as an app: a linked, valid Web App Manifest with install-ready icons and a theme colour.                                                                                                                                 | the web app manifest and service worker                                 |

## Where the hints come from

Each hint records its origins (the upstream check, a link to it, a summary and the licence) in its metadata, and the full list of references with their licences is in `src/core/sources.ts` (and in the [References](../../README.md#references) of the root README). Hints written for this package, with no upstream, are in the `original` group.
