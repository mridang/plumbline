# plumbline

About 280 checks for a website and the services around it: security headers, TLS and certificates, DNS, email authentication, Open Graph and SEO, privacy, agent readiness, and the well-known files (`robots.txt`, `security.txt`, `llms.txt`, `ai.txt`). Every check is ported from a public reference, such as Mozilla Observatory, OWASP, Webbkoll, internet.nl, MDN, isitagentready and Roctify, with its original rules, thresholds and wording kept (see [References](#references)).

The checks are [webhint](https://webhint.io) hints, and everything else in this repository is a way to run them.

| Package                                                                 | What                                                         |
| ----------------------------------------------------------------------- | ------------------------------------------------------------ |
| [`@mridang/webhint-hint-plumbline`](packages/hints/README.md)           | The hints, the group presets and the full list of checks     |
| [`@mridang/webhint-formatter-plumbline`](packages/formatter/README.md)  | An HTML report for webhint, sectioned and filterable         |
| [`@mridang/lighthouse-plugin-plumbline`](packages/lighthouse/README.md) | A Lighthouse plugin with the checks Lighthouse can run       |
| [`@mridang/plumbline`](packages/cli/README.md)                          | The `plumbline` CLI, which runs every check                  |
| [`@mridang/plumbline-skills`](packages/skills/README.md)                | The agent skill and the Claude Code plugin that run the CLI  |
| [`@mridang/plumbline-docker`](packages/docker/README.md)                | A scan server, shipped only as the `mridang/plumbline` image |
| [`@mridang/plumbline-web`](packages/web/README.md)                      | The plumbline website, on Cloudflare Workers (private)       |

## How to use it

The npm packages and the Docker image are released together; until the first release, [build the packages from this repository](packages/hints/README.md#before-the-first-release) or [build the image](packages/docker/README.md#build-the-image).

### On the website

Go to [plumbline.apps.mrida.ng](https://plumbline.apps.mrida.ng) and type a domain. Every check runs on the server, so nothing needs installing. Sign in with Google to keep a list of domains, choose which checks run for each, and keep their reports. See [`packages/web`](packages/web/README.md).

### Choosing the rules of a repository

A repository connected through the GitHub App can keep a `plumbline.yaml` in its root to choose which rules apply to its sites (`extends`, `rules`, `environments`, `issues`, `dispatch`). Editors can check it against the [JSON Schema](https://plumbline.apps.mrida.ng/schemas/plumbline.schema.json): put `# yaml-language-server: $schema=https://plumbline.apps.mrida.ng/schemas/plumbline.schema.json` on the first line. See [Choosing the rules with plumbline.yaml](packages/web/README.md#choosing-the-rules-with-plumblineyaml).

### From the command line

```sh
npx @mridang/plumbline scan example.com
npx @mridang/plumbline scan example.com --group tls,email --fail-on warning
npx @mridang/plumbline checks --group owasp
```

It runs every check from Node with a real Chrome, exits 1 when a finding is at or above `--fail-on` so it can gate a CI job, and prints text, JSON or the HTML report. A Chrome-family browser must be installed. See [`packages/cli`](packages/cli/README.md).

### With a coding agent

The [skills package](packages/skills/README.md) teaches an agent (Claude Code, Codex, Cursor, GitHub Copilot and others that read the Agent Skills format) to audit a site with the CLI, read the findings and explain the fixes. Install the skill with:

```sh
npx skills add mridang/plumbline
```

In Claude Code it is also a plugin, with an `/plumbline:audit <url>` command that runs the scan for you:

```text
/plugin marketplace add mridang/plumbline
/plugin install plumbline@plumbline
```

The skill runs `npx @mridang/plumbline`, so the agent needs Node 22 and a Chrome-family browser. See [`packages/skills`](packages/skills/README.md) for copying the skill by hand.

### From an assistant (MCP)

Add `https://plumbline.apps.mrida.ng/mcp` as a connector in ChatGPT, Claude or any MCP client, sign in with Google when asked, and approve. The assistant can then list the checks, keep your domains, choose their checks and read their reports. See [Connecting an assistant](packages/web/README.md#connecting-an-assistant-mcp).

### In webhint

```sh
npm install --save-dev hint @hint/connector-puppeteer @hint/parser-html @mridang/webhint-hint-plumbline
```

Extend the group presets you want in `.hintrc`, or list single hints as `@mridang/webhint-hint-plumbline/<id>`:

```json
{
  "formatters": ["stylish"],
  "extends": [
    "./node_modules/@mridang/webhint-hint-plumbline/configs/observatory.json",
    "./node_modules/@mridang/webhint-hint-plumbline/configs/email.json"
  ],
  "hints": {
    "@mridang/webhint-hint-plumbline/hsts": ["default", { "profile": "owasp" }]
  }
}
```

```sh
npx hint https://example.com/
```

The groups, the sections, the hint options and the table of every hint are in [`packages/hints`](packages/hints/README.md).

### The report formatter

```sh
npm install --save-dev @mridang/webhint-formatter-plumbline
```

```json
{
  "formatters": ["@mridang/webhint-formatter-plumbline"]
}
```

webhint then writes `hint-report/<site>.html`, one self-contained page with the findings grouped by section, each hint's description and sources, and a filter by source. See [`packages/formatter`](packages/formatter/README.md).

### In Lighthouse

```sh
npm install --save-dev lighthouse @mridang/lighthouse-plugin-plumbline
npx lighthouse https://example.com/ --plugins=@mridang/lighthouse-plugin-plumbline
```

The plugin adds a "Webhint extra" category with the 143 checks whose data Lighthouse already gathers (headers, Open Graph, SEO, structured data, privacy). See [`packages/lighthouse`](packages/lighthouse/README.md).

### With Docker

```sh
docker run --rm -p 8080:8080 mridang/plumbline
curl -s localhost:8080/scan -d '{"url":"https://example.com/"}'
```

A small HTTP server that scans a URL with a real Chromium and answers with the findings as JSON, for end-to-end tests in any language. See [`packages/docker`](packages/docker/README.md).

## Development

This is an npm-workspaces monorepo. Every command runs through devbox, from the repository root, and operates over every workspace:

```sh
devbox run -- npm run build                                  # compile every workspace to dist/
devbox run -- npm test                                       # every test, the web app's included
devbox run -- npx jest --coverage=false packages/cli         # one package's tests
devbox run -- npx tsc --noEmit -p tsconfig.jest.json         # type check sources and tests
devbox run -- npm run lint                                   # eslint
devbox run -- npx prettier --write <paths>                   # format
```

[`AGENTS.md`](AGENTS.md) explains how a hint is written, registered and tested, and the standing rule for HTTP header coverage.

## Where each check comes from

Every check records the public reference it was ported from (its origins, in `packages/hints/src/core/origins.ts`), and the same name is a source group, so a whole provider can be switched on with `--group <provider>`. Checks written for this repository have no upstream.

### Roctify

[Roctify's free SEO checker](https://roctify.com/tools/seo-checker) runs 39 checks in six categories. Each one maps to the hints below, and the `roctify` group runs them all. Roctify publishes the names of its checks but not their thresholds, so the limits in the new hints (word count, URL length, response time, HTML size and the like) are ours and are stated in each hint's doc comment. Roctify's Google PageSpeed section (Lighthouse score, LCP, CLS and TBT) is not a check on the page and is not implemented.
